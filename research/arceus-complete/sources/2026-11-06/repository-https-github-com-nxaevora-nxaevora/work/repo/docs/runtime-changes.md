# Runtime changes in the vendored ScarletNX

ScarletNX is part of this repository (`third_party/ScarletNX`, from upstream commit 8efbf9c4). The changes below
were patch files before. They are now ordinary commits in the source, and the patch files are deleted. The names
`0001` to `0017` are the old patch numbers. The text says what each change does.

| Change | What it does |
| --- | --- |
| nvn-compute-qmd-size-limits | The native compute QMD builder refuses a constant buffer size that would lose bits when packed into the 17-bit size field. Uniform slots 0 to 4 are checked after 256-byte rounding, and program constant buffer 1 is checked after its existing padding. Driver-only uniform slots keep their 32-bit size limit. A refusal leaves the output untouched and identifies the uniform slot. Test `nvn_params` checks the boundaries, wraparound sizes and driver-only descriptors without game files. Update 1.1.1 recompiles and runs. The established path renders the opening dialogue. Native-path captures are black with both the original and patched builder, and a 120 s patched run reaches no compute dispatch. The compute gameplay effect is not verified. |
| 0001-native-mouse-input | Native mouse input. The mouse is captured and drives the right stick. The left button is ZR and the right button is ZL. A controller input makes the controller the active input. Hold Alt to free the cursor. New settings `mouse_*` (look, sensitivity, vertical sensitivity, invert Y, dead zone offset, curve, overdrive). See `docs/input-analysis.md` and `docs/camera-analysis.md`. |
| 0002-global-red-add-u64 | Shader translation of `RED.E.ADD.64` (a 64-bit add into global memory, size 2 of `RED`). The translator refused it, so one draw in each frame was skipped. The module declares `Int64Atomics`, each global buffer gets a 64-bit view on the same binding (decoration `Aliased`), and the device enables `shaderBufferInt64Atomics`. A device without the feature refuses the program as before. A regression test with a `spirv-val` check is in `tests/shader_direct_regressions.c`. See `docs/shader-analysis.md`. |
| 0009-keyboard-remap | The keyboard map as a setting. The new setting `keyboard_map` (section Keyboard) lists `Button:Key` words, for example `ZL:Q A:F LStickUp:Up`. A button that the text names loses its default keys. A key that the text names belongs only to the buttons named with it. `None` frees a button. A key name is the SDL name, with `_` for a space. Escape, F1 to F12, Pause and Alt are reserved. A word that cannot be read is logged and the map stays. See `docs/input-analysis.md`. |
| 0010-ini-store-256 | The store of the game's `.ini` held 128 keys, and the file already had 129 (the log said `more than 128 keys, renderdoc_frames and those after it are left out`). A key after the 128th was dropped at the read and so erased at the next write of the file. A key that the user added, such as `keyboard_map`, went this way. The limit is now 256. |
| 0012-native-mouse-guest-words | The runtime side of the native mouse look. The setting `mouse_native_address` (0 = off) is the guest address of a 64 bit word (two floats: yaw in radians, pitch in units of the camera arc). The mouse motion is added to it as it arrives, in place of the stick, and the game's code patch `native-mouse-look.pchtxt` takes it. Settings `mouse_native_yaw` (1400) and `mouse_native_pitch` (1000, 500 from `0016`), in millionths for each mouse count, and `mouse_invert_x` and `mouse_invert_y` turn the directions. At most 0.5 of each waits for the game. See `docs/camera-analysis.md`. |
| 0013-imgui-windows | The in-game Dear ImGui windows (plan: `docs/imgui-plan.md`, review: `docs/imgui-review.md`). It is one patch of ten steps that were once separate patches. Dear ImGui 1.93.0 (MIT) is a pinned CPM package (`cmake/dependencies.cmake`, SHA-256 of the release archive). The core and the Vulkan backend (loaded through volk) are built into the renderer and draw a frame over the presented image (`gpu/vk/imgui.c`, `imgui_glue.cpp`). The fonts are read from `fonts/` in the game's data folder (`Roboto-Variable.ttf`, `NotoSansJP-Regular.otf`, from `assets/fonts`), and the built-in font is the fallback. The theme is ImGui's dark theme with the accent `#46478B` and an alpha of 0.94 on the whole window (`imgui_style.cpp`). The window's events go to a queue (`imgui_input.c`, `backend/imgui_sdl.c`) that merges motion and never drops a key, button or focus change, and the frame publishes what the windows want (mouse, keyboard, text, release of the cursor, the input method's place). A menu bar (About, Settings, Mods, Cheats, Debug) shows when the cursor is at the top of the picture, and Alt frees the cursor from the mouse look. The Debug window shows the GPU (NVML, picked by the Vulkan device's UUID), the processor and memory, the frame times, the cost of a frame and the display. The game's software keyboard (the player's name) is a window too: `overlay.c` keeps the state and the ticket protocol, and the old box returns when the windows do not run or the Vulkan backend reports an error. The windows replace the game's old menu (F2, Back, Home, the on-screen menu button), and `legacy_menu` brings it back. New settings `imgui` (default 1), `imgui_test` and `legacy_menu` (default 0), section Debug. While the game presents nothing for a quarter second (a loading interval), the renderer's refresh also runs when the windows have something drawn or an input event waits, so the windows keep updating and the menu bar still opens. |
| 0014-gui-group-icons | The launcher test `gui_sdl_events` wants an icon for the group of each section of `settings.txt`. The sections Mouse (`0001`) and Keyboard (`0009`) had none, so the test failed. Mouse gets the pointer icon and Keyboard the key icon. |
| 0015-imgui-input-test | The host test `imgui_input` for the event queue of the ImGui windows: positions and wheel steps merge, the order of events holds, a full queue removes motion and keeps a key, a button or a focus change. |
| 0016-settings-controller-keyboard | The window "Controller&Keyboard" of the ImGui windows (menu Settings, same name for the entry). It is one patch of five steps that were once separate patches. The pages are the sections Mouse and Keyboard of `settings.txt` (the list `PAGES` in `imgui_settings.c`), and a row is made from the setting's table row, so the window and the `.ini` cannot differ. An int with words is a choice, an int is a slider (a field when its range is wider than 100000), a float is a slider, and the help of the setting is the tooltip. A startup setting says that it applies at the next start, and a setting that the command line holds is disabled. A change waits in a small queue (`backend_setting_request`) and the main thread applies it in `video_poll` through the new `options_change` (`options.c`): `ini_check`, the same apply as a reload, then `ini_set`. The row `mouse_native_address` is not shown (a guest address that the launcher sets). While the pointer is over a slider or a choice, Left and Right move it by the setting's step (Shift: ten steps, Ctrl: one unit), and the window asks for the keyboard, so the game gets no arrow key. The Keyboard page has the key bindings: the 24 buttons with the keys that send them (a default key is dimmed), Bind (the next key press, taken in `video_poll` by scancode before the windows and the game see it, Esc cancels, F1 to F12, Pause and Alt are not taken), None, Default and Reset all. The window leaves the new text of `keyboard_map` for the main thread, which applies it with `options_change` (`g_keybind` belongs to that thread). A capture ends on Esc, on a loss of the focus and on a key that has no name that gives the same key back, and the bindings follow a `--keyboard_map` on the command line. Each key's release clears the buttons that its own press set. `keyboard_map_set` is split in `keybind_compile`, which the view uses too. The patch also sets the defaults: the keys A: F, B: Left Shift, X: R, Y: Space, L3: Left Ctrl, L: Q, R: E, Plus: G, Minus: M, the arrow keys for the D-pad and W, A, S, D for the left stick (ZL, ZR, R3 and the right stick have no key), the F1 help text, and `mouse_native_pitch` 500 (was 1000). The menu bar no longer comes up for a popup of another window (a combo closed at once because the bar took the focus), and it stays hidden when the program starts with the cursor outside the window (`imgui_sdl.c` gives the windows a position only when the window has the mouse focus, and no position when the cursor leaves it). The Controllers page (the section Controllers) shows the rows that every player shares (swap A/B, stick dead zone, vibration, background input, Joy-Con pairing) and the button map: for each of the 16 controls of a gamepad, a choice of the console button that it sends (None, A to Down). A button that another control sends goes to the old control of this one, so no button is lost. The map is `gamepad_map` (A and B swapped as `gamepad_swap_ab` says), "Reset to the console's layout" clears it, and the main thread saves it with `options_change` (`backend_padmap_request`). The rows of each player (`gamepad_pN_*`) are not shown, and a player's own `gamepad_pN_map` is not edited. |
| 0017-display-window | The window "Display" (menu Settings), with the tabs Display, Graphics and Performance (sections of `settings.txt`). The pages carry the window that shows them (`imgui_settings.c`), and one function draws both windows. A setting that is chosen from a short list is a combo box: the resolution scale (0.5x to 4x, with the size at 1920 x 1080 for 1x) and the anisotropic filtering (the game's, 2x to 16x); a value that is not in the list shows as custom. A startup setting that the window changed shows the saved value and "Saved. Start the game again to apply it." (`options_restart_value`, kept by `options_change`). `vsync` has three values: 0 off (immediate, else mailbox, else FIFO), 1 on (FIFO, the default), 2 on (mailbox, else FIFO). The Debug window shows the size the game renders at (scaled) and the V-sync mode. The picture's alpha is made 1 before it is presented, with a pipeline that writes only alpha (`ui.c`): the game's alpha channel made the HUD leave ghosts over the picture with mailbox and immediate (`docs/present-alpha.md`). |
| 0018-fxaa | The setting `anti_aliasing` (section Graphics, 0 off, 1 FXAA, default 0) and the pass `postfx.c`. The frame that the game presents goes through one fragment pass into an image of its own (same format and size as the render target), and the present blits from that image. The on-screen controls and the windows are drawn after the pass. The render targets and the guest memory stay as the game drew them. The shader `fxaa.frag` is a new implementation of the edge-directed blur of the FXAA whitepaper (Timothy Lottes, NVIDIA, 2009). The Display window shows the mode in the row Anti-aliasing. |
| 0019-scaling-filter | The setting `scaling_filter` (section Graphics, 0 bilinear, 1 bicubic, default 0). Bilinear is the blit of before. Bicubic draws the frame (or the anti-aliasing image) into the window image over the letterboxed rectangle with a Catmull-Rom filter over 4 x 4 texels (`shaders/bicubic.frag`, `postfx.c`). It filters in gamma space, so an sRGB frame does not ring. The Display window shows the filter in the row Scaling. FSR1 and its sharpness are next. |
| 0020-smaa | The value 2 (SMAA) of the setting `anti_aliasing`. `shaders/smaa.frag` is a port to GLSL of SMAA 1x from SMAA.hlsl (Jimenez, Echevarria, Masia, Navarro, Gutierrez, MIT, the license is in `shaders/smaa/LICENSE.txt`), preset HIGH, luma edges, no predication or temporal parts. It builds three passes with macros: the edges (RG8 image, cleared to zero, luma taken in gamma space for an sRGB frame), the blending weights (RGBA8 image, with the area and search tables) and the blending into the anti-aliasing image of `postfx.c`. The two tables are the DX9 area texture and the search texture of the SMAA repository, embedded by `cmake/smaa_tables.cmake`. `postfx.c` now keeps its images as `Target` and draws every pass with `fullscreen_pass`. |
| 0021-nvn-submit-trace | With `nvn_trace=1`, the first 40 GPFIFO submissions are logged (`gpu-submit:` lines): the channel, the number of entries, the syncpoint increments, the fence, the first entries and the last entry with its first 24 words. It shows what a queue call adds to the command buffers of the game (phase 6, `docs/nvn-survey.md`). Nothing changes when the setting is 0. |
| 0022-nvn-diagnostic-3a | With `nvn_trace=1`, the first 3 GPFIFO submissions list every entry and show all words of the entries of 64 words or fewer (the entries that the NVN library adds). The first 40 calls of `nvnTextureBuilderGetStorageSize` and `GetStorageAlignment` log the result and 128 bytes of the builder (`nvn-size:` lines). It is the diagnostic of step 3a (`docs/nvn-design.md`, 2-6). Nothing changes when the setting is 0. |
| 0023-nvn-native-base | The setting `nvn_native` (startup, 0 or 1, default 0) and `gpu/nvn_native.c`. With 1 the host hooks `nvnBootstrapLoader` and `nvnDeviceGetProcAddress` below the trace hooks, and puts a host handler in the dispatch slot of each resolved function. No host handler exists yet, so every function gets the missing-function handler: the first call is logged (`nvn-native: not implemented: <name>`) and it returns 0, and the exit report lists the calls. `gpu/nvn_objtab.c` is the table of the host's records of NVN objects, keyed by guest address (test `nvn_objtab`). With 0 nothing changes. With 1 the game does not draw. |
| 0024-nvn-value-trace | With `nvn_trace=1`, each distinct `nvnDeviceGetInteger` query (what and value) and the first distinct calls of six other query functions (queue memory size, texture and sampler pool size, memory pool flags, buffer builder size, timestamp) are logged as `nvn-value:` lines. They are the answers that the host handlers must give (phase 6, step 3b). |
| 0025-nvn-device-words-trace | With `nvn_trace=1`, the first calls of `nvnDeviceGetTimestampInNanoseconds` and `nvnQueueBuilderGetQueueMemorySize` also log the device words and builder words that the library reads (`nvn-value: device ...` and `nvn-value: queue builder ...` lines). They gave the constants of the host handlers of step 3b-3. |
| 0026-nvn-native-g1 | With `nvn_native=1`, host handlers for the device and queue functions (30 functions: device builder, `DeviceInitialize`, `DeviceGetInteger`, the window origin and depth modes, `DeviceGetTimestampInNanoseconds`, the queue builder, `QueueInitialize`). The records are in a side table, and the game's object memory is not written. The pure parts are in `gpu/nvn_params.c` (test `nvn_params`). |
| 0027-nvn-native-diagnostics | The trace stops with the function name when it would wrap a slot that already holds a trace wrapper (a wrapper that calls itself). With `nvn_native=1` each host handler logs `nvn-native: host handler for <name> at <address>` when the game resolves it. Both are for the hang of the first run of 3b-3. |
| 0028-nvn-native-return | Every host handler of `nvn_native=1` runs through `native_call` in `gpu/nvn_native.c`, which sets `c->pc` to the saved x30 after the handler. A guest function ends with RET, which sets `c->pc`, and the generated code of the caller compares `c->pc` with its return address (`check_return`). Without this step the caller ran its last block again, so `nvnDeviceBuilderSetDefaults` was called more than 10^9 times. |
| 0029-nvn-native-pools | With `nvn_native=1`, 13 host handlers implement the memory pool builder, memory pool lifetime and queries, and texture and sampler pool links and counts. Host records hold all object state. Virtual pools and imports fail with a log line. `gpu/nvn_params.c` holds the storage checks, flag normalization and a page-aligned GPU address allocator, with cases in test `nvn_params`. The host page size is 0x1000. GPU page-table mapping is not connected: nvdrv has no public unmap and reservation interface for these host ranges. Sampler initialization does not write descriptors. |
| 0030-nvn-native-textures-samplers | With `nvn_native=1`, 29 host handlers implement the sampler builder, sampler initialization and pool registration, the texture builder, storage queries and texture initialization. Host records hold all object state. The pure sampler encoder writes eight descriptor words through the memory pool CPU base. The pure texture layout code gives size, alignment and layout. Texture addresses use the pool GPU base plus offset. Texture kind stays 0, and imports fail with a log line. Device inputs that were not measured use named provisional constants. Test `nvn_params` checks the encoder and layout, and can compare an external `nvn-size:` log. |
| 0031-nvn-native-texture-views | With `nvn_native=1`, 15 host handlers add texture dimension and packaged layout setters, texture views, width/height/stride getters and texture pool registration. Host records hold view fields and set flags. The pure encoder produces eight descriptor words from texture layout, an optional view, device words and a guest format record. Both descriptor types share CPU destination lookup. Invalid inputs give one log line and no write. Device initialization values are verified, except provisional +0x1b1c=1, which preserves the 40 archived size results. Test `nvn_params` checks synthetic descriptor vectors, index checks, row clamping and packaged tiles. |
| 0032-nvn-native-windows | With `nvn_native=1`, host records handle window builders, window initialization, interval and crop settings, and sync initialization. `WindowInitialize` reads the texture pointer array at call time, accepts 1 to 4 known texture records, and leaves the window record unchanged on failure. Guest object memory is not written. Acquire, wait and finalize functions remain missing. Test `nvn_params` checks builder defaults, setters, count limits and crop rules. |
| 0033-nvn-native-window-acquire | With `nvn_native=1`, `WindowAcquireTexture` paces outside the object lock, selects a FREE image, marks it ACQUIRED, signals its sync and returns its index. If no image is FREE, it logs and returns failure. `SyncWait` returns 0 for signaled and 3 for unsignaled or unknown syncs. Tests `nvn_params` check image selection and both sync states. |
| 0034-nvn-selftest-harness | New setting `nvn_selftest` (needs `nvn_trace=1` and `nvn_native=0`). At the first `nvnQueueInitialize` the selftest calls the library function and the host handler with the same arguments on the calling guest thread, restores the CPU context after each call, and compares the results. Its objects are in a 64 KiB block from `kmem_alloc`, not in the game heap. The comparer (`nvn_selftest_cmp.c`), the arena (`nvn_selftest_mem.c`) and the recording `Renderer` (`nvn_selftest_rec.c`) are pure parts with host tests. The first cases are `nvnDeviceGetInteger` (the word written, kind M) and the texture builder storage size, alignment, width and height (kind R). `nvn_trace.c` gives the library entry by name, and `nvn_native.c` gives the host handler by name. Without the setting nothing changes. |
| 0035-nvn-review-p1 | Two fixes from the review of 3b. With `nvn_native=1` and `nvn_trace=1` together, each resolver hook (`nvnDeviceGetProcAddress`) is now installed once. Before, the second bootstrap lookup made the two hooks call each other until the stack ended. `SamplerPoolRegisterSampler` and `TexturePoolRegisterTexture` now check the index against the descriptor count, the descriptor range against the memory pool, the address sum, and the write permission of the destination before they write. A failed check logs and writes nothing. Test `nvn_params` checks the range function at both ends. |
| 0036-nvn-review-p2 | Fixes from the review of 3b. A failed `MemoryPoolInitialize` or `TextureInitialize` removes its record, so later calls cannot use it. `TextureInitialize` fails with a log line when the layout does not fit in the memory pool. Texture and buffer sizes use 64-bit math. The target names are corrected to the library's numbers (5 multisample, 6 multisample array, 7 rectangle), with no change of behavior. A sampler wrap above 7 and a texture swizzle above 5 fail at registration with a log line, and are no longer mapped to a default. `nvnDeviceGetInteger` answers 0 only for a `what` above 0x62 (the library's switch default), and writes nothing for an unknown `what` below it. `WindowAcquireTexture` checks write permission of the index pointer. `SyncWait` on a sync that is not signaled logs the sync, its state and the timeout. The trace keys the queries that take only an object by their result, and a zero key is valid. The selftest recorder keeps the compute launch description, and the selftest checks guard bytes around the `DeviceGetInteger` output word. The selftest also logs the device bytes at +0x1b18 and +0x1b1c, because the source of the compression switch is not known. Tests `nvn_params`, `nvn_selftest_rec` and `nvn_selftest_cmp` check each rule. |
| 0037-nvn-gpu-range | New public functions `nvn_gpu_map_range` and `nvn_gpu_unmap_range` in `nvdrv`. With `nvn_native=1`, `MemoryPoolInitialize` maps the pool storage at its GPU address and `MemoryPoolFinalize` unmaps it, so the renderer can read a pool by GPU address. The map fails (returns 0) for an unaligned or out of range argument and for a range where any page is mapped already. A failed map fails the pool initialization with a log line. The unmap clears only the pages that still show the pool storage. Test `nvdrv_service` (`test_nvn_gpu_range`) checks the refusals, the overlap and the unmap that keeps a page mapped over it. |
| 0038-nvn-native-buffers | With `nvn_native=1`, host handlers for the ten Buffer and BufferBuilder functions. A buffer record holds the pool address, the pool generation, the offset and the size. `BufferInitialize` fails with a log line for an unknown or null pool, a physical pool (the library does this too) and a range outside the pool (the host adds this check). `BufferMap` returns the pool map pointer plus the offset, and 0 for a pool without CPU access. `BufferGetAddress` returns the pool GPU address plus the offset. A buffer whose pool ended returns 0 with a log line (the first 8 times). Test `nvn_params` checks `nvn_buffer_check`. |
| 0039-nvn-native-command-buffers | With `nvn_native=1`, host handlers for sixteen CommandBuffer functions: Initialize, Finalize, SetMemoryCallback, SetMemoryCallbackData, AddCommandMemory, AddControlMemory, BeginRecording, EndRecording, CallCommands, SetTexturePool, SetSamplerPool, SetRenderTargets, SetViewports, SetScissors, ClearColor and Barrier. They record ops in a host list (`gpu/nvn_cmdlist.c`) and write nothing into the game's command or control memory. `EndRecording` publishes the list and returns a host handle (0 outside a recording). An op outside a recording, or with an unknown pool, texture, view or handle, is dropped with a log line (the first 16). Nothing replays the lists yet, so the other CommandBuffer functions still report as not implemented and the game draws nothing. Test `nvn_cmdlist` checks the op list, the handles, the references and the release of CALL targets. |
| 0040-gpu-channel-open | New public function `gpu_channel_open` in `gpu.c`. It makes the `GpuChannel` of a syncpoint id with the reset state and returns it, without a submission. The host NVN path takes the id from `syncpt_alloc` and writes engine methods on this channel on the GPU thread. `gpu_channel_close` ends it as before. An id past the channel count is fatal, as in `gpu_submit`. |
| 0041-nvn-replay-module | New pure module `gpu/nvn_replay.c`. `nvn_replay_list` walks the ops of a host command list and turns them into Maxwell 3D methods through callbacks (`NvnReplayEnv`). It covers the texture and sampler pools, viewports, scissors, ClearColor, Barrier (counted, no method), CALL (up to 8 levels) and SetRenderTargets (done by the caller). A bad op is skipped with a fault call and counted. Nothing calls the module yet, so no behavior changes. Test `nvn_replay` checks the method words. |
| 0042-nvn-rt-words | New pure module `gpu/nvn_rt.c`. `nvn_rt_emit` turns up to 8 color render target textures into the Maxwell 3D methods of `nvnCommandBufferSetRenderTargets`: RT_CONTROL, one 8 word block for each target, the format-0 disable of the unused slots, the null depth words, SURFACE_CLIP and the sample mode. It checks every target first. A request it does not support (depth, a view, a non 2D target, more than one level, a linear target, a compressed format, a target smaller than one tile) is refused with one fault call and no method write. The clip limit (device +0x18) is an argument: its source is not found yet. Nothing calls the module yet, so no behavior changes. Test `nvn_rt` checks every word and each refusal. |
| 0043-nvn-replay-host | With `nvn_native=1`, `nvn_native_replay_env` in `nvn_native.c` fills the `NvnReplayEnv` of the replay: methods go to `maxwell3d_method` on a private channel, and lists, descriptor pools and render target textures are read from the host records under the lock. `SetRenderTargets` is refused with a log line while the clip limit (device +0x18) is 0. `nvn_list_find` pointers stay valid while the list lives (each list slot is its own allocation), because the GPU thread reads a list while the game publishes another. `nvn_selftest` logs the device words +0x18, +0x19d8 and +0x1a04. Nothing calls the env yet, so the game does not change. Test `nvn_cmdlist` checks the stable pointer. |
