New engine findings

1. Physics has elapsed preparation beside the fixed-step main world.
Component jobs before main physics use elapsed channel1 dt. One path converts
target-transform differences to velocity-like outputs using1/dt; another passesdt and its
inverse into support checks. Separately, the second world family directly uses
supplied dt and updates indexed transforms. Its exact gameplay ownership is
still unresolved. A blanket multiplier in the shared solver would also modify
these already-variable worlds. Normal visible movement does not prove all free
dynamic bodies have correct timing, either.

World+5B8 is an existing32-bit postsolve serial shared across worker contexts.
Constructor and both solve implementations establish its initialization and
increment. One guarded read of that scalar is now appended to the existing
sampled solver log. No extra hook, guest write or timing behavior was added.
The parser preserves raw serial/count/time/simulation records and does not
automatically infer lifetimes or rates. This field was NOT in the completed
capture; the staged next candidate is needed to observe it.
Detailed evidence: arceus-physics-research-pass6.txt.

2. Dialogue has separate readiness, automatic advance and close-delay controls.
The readiness field changes1->2 at the end of one ordinary text-wrapper call;
it is not a seconds delay. Optional auto-advance bytes only govern specific
modes, and one mode permits manual input to bypass that threshold. A timed
message subtype has a separate signed countdown after state6, closing on the
N+1th eligible visit when initialized toN. The base subtype has no such clock.

An isolated fast-finish fixture can reuse one fresh button mask across two
terminal text boundaries in one parent call; the one-shot flag is consumed.
This does NOT demonstrate two queued NPC messages or live use of that mode.
The field constructor enablesD8, notD9; it startsD9 at zero. No global dialogue
throttle or speculative input cooldown was installed.
Detailed evidence: arceus-dialogue-research-pass6.txt.

3. AI turning needs coherent angular progress and completion.
Turn/TurnKey retain authored degrees and frames. They apply one quaternion step
per eligible callback even when their completion counter advances by more than
one. Correcting only the counter would produce the wrong total rotation.
The original yaw setter adds another issue: float rounding near zero heading
can erase tiny fractional steps. A controlled1-degree turn stalled at120
callbacks/s with naive fractional rotation. Carrying only the setter's small
angular residual produced the intended endpoint and preserved an injected
external orientation change. The original angle is also needed to preserve
multi-revolution motion that a quaternion alone cannot represent.

This is a candidate design tested around original arithmetic, not a live fix.
Scheduler windows, entry/reentry, object lifetime and writer order need live
evidence before rollout. Existing grouped callbacks can differ even at30FPS.
Detailed evidence: arceus-ai-turn-research-pass6.txt.

4. Resolution has explicit scene modes beyond the automatic governor.
Original mode setters confirm custom width/height scale, half scale and a
separate overriding mode. A transition saves requested mode and requests7,
which applies(.5,.5) only if no override supersedes it; a later branch restores
the saved request. It does not preserve all resolution state, and complete
cancel/error-path restoration is unproven. No stuck-resolution defect is claimed.
Disabling the automatic governor cannot by itself guarantee full scene size.
Tests verify parameter writes, not final render dimensions or1440p quality.
Detailed evidence: arceus-resolution-research-pass6.txt.
