RESULT

Three different advance controls are now distinguished:
1. Text+114 is a readiness latch promoted from1 to2 at the end of an ordinary
   FBFBD0 processing call. It is not a seconds timer or minimum-duration field.
2. Text+A2/+A3 are an optional byte threshold/counter for automatic advancement
   in text mode2 or3. Mode1 is manual; mode3 permits manual input to bypass the
   automatic threshold. These bytes are not a universal input debounce.
3. The timed active-message wrapper has a signed +9C countdown AFTER its message
   reaches state6. It requests close when the OLD value is<=0. The base wrapper
   has no such countdown. Queued2485A40 uses the timed subtype.

An unchanged-instruction fixture also demonstrates a narrow input-reuse edge:
with message+D9 enabled, the fast-finish call and the following normal call can
accept the same fresh mask at two successive terminal text boundaries within
one27379B8 invocation. The consumed one-shot text+17A does not repeat this way.
This is NOT proof of advancing two queued NPC messages, nor proof that live NPC
dialogue uses+D9. The field constructor initializes+D9 to zero and the traced
field wrapper does not enable it.

Final isolated result: 1752 checks, zero failures, 26 compiled entries from
12 complete functions plus dynamic internal entry points. No runtime/package,
save, asset or shared output was edited. No game operation was performed.

TEXT+114 READINESS LATCH

The ordinary FBFBD0 wrapper loops around2B315E8, then atFBFC4C..5C promotes
T+114==1 to2. Promotion happens after the inner processing loop ends, so a fresh
wait state created during that loop is not immediately armed within the same
loop. The embedded-wait and external-condition early returns bypass promotion.

Base processor2B315E8 requires T+114==2 before calling manual advance predicates:
  state2, T+BC not1/2:2B31658..74 ->virtual+68 (FC1078).
  state0, T+BC==0, mode1:2B3182C..48 ->virtual+70 (FC10E4).
  state0, mode3:2B31D24..40 tries the same predicate before automatic delay.
The readiness latch is reset/replaced at state transitions; text replacement
2B311F0 clears it at2B31480, sets text state4 at2B31470 and clears auto counter
+A3 at2B3147C. Examples of state changes setting readiness1 include2B3177C,
2B3195C,2B31D18,2B31DF4 and2B31FA4.

No wall-clock minimum delay follows from this latch. With one ordinary wrapper
call per presentation frame, one-call boundaries would shorten at higher FPS;
that callback-to-presentation relationship remains a live observation question.
The fixture confirms readiness1 rejects a manual state0/mode1 attempt, promotes
to2, and the following wrapper accepts the still-present fresh mask. The input
predicate does not consume/clear that shared mask. This does not simulate a new
physical press or claim that the input collector repeats a held button.

TIMED ACTIVE-WRAPPER SUBTYPE: NEW POST-COMPLETION COUNTDOWN

2485338 constructs the base A via24841E4, then installs vtable415DBE0. It copies
descriptor+28 to A+9C and A+A0 at2485374..78, and descriptor+2C to A+A4 at
248537C..80. Its virtual+40 is2485390; base vtable415DB18+40 is RET24851FC.

2485390 after-update operation:
  if M+80!=6: return unchanged;
  if signed old(A+9C)<=0:2484ECC(A) ->2737C00(M,1), request animated close;
  A+9C-=1, including after the close request (24853D8..DC ->24853BC).
No seconds conversion or clock read appears. From initial positive N, close is
requested on state6 visit N+1. Counts-1/0 close on the first eligible visit.
The final value is-1 for nonnegative starting counts, -2 for initial-1.
A+A0 remains unchanged in this method. Other descriptor fields are not assigned
unverified semantic names here.

Concrete allocation routes:
  queued/request2485A40 ->2485E48 ->2487E04 ->2485338 (timed subtype).

 2485EE4 constructs24841E4 directly at2485FC8 (base/no after-update countdown).

Do not infer timed subtype solely from a message layout or from M state6.

2484ED8 invokes A virtual+40 AFTER the current27379B8 call. Thus the first
countdown decrement can occur in the same wrapper update that reaches M state6.
This is a completion-to-close hold, separate from the latch and auto-advance
counter. It could shorten if this wrapper's calls scale with FPS, but live
descriptor values, subtype and cadence have not yet been observed.

MANAGER-LEVEL MULTIPLICITY LIMIT

24858F4's active branch calls2484ED8 once and then clears A if M state7. It does
not loop into the next queued descriptor that same invocation. Its no-active
branch may create one queued wrapper via2485A40, but does not run its normal
active update immediately.2485A40 returns the existing active object when one
exists. This inspected path supplies no evidence of draining several queued
NPC messages from repeated A/B events in one manager update.
Other owners/callers, callback side effects and live scheduling could matter;
this is not a global one-message-per-frame proof.
