ARCEUS 1.1.1 — REAL-TIME EVENT COORDINATION CLOCKS
Fifth offline pass, 2026-11-06. All addresses are hexadecimal main-relative.

RESULT

The four fixed 1/30 sites belong to event_script::RealTimeEventManager's
catch-up / warning / navigation recovery flow. This owner identification is
confirmed by local type-name strings and the script registration table. The
three long-delay fields are not generic dialogue/typewriter counters.

New concrete distinctions:
  +190: a configurable, capped delay while IsWaitCatchUp remains true.
  +198: a six-second overall recovery timeout, then a fade/reposition fallback.
  +1A0: cumulative in-range time; stops pathfinding after two nominal seconds.
  +19C: a one-second hold between repositioning and the fade back in.
These remain live-cadence risks, not demonstrated active gameplay bugs. No game
was launched, driven or closed. No runtime/package/shared report, save or asset
was changed. All new evidence and this report are private in work/pass5-events/.

WAIT-CATCH-UP GATE AND +190

168038C (IsWaitCatchUp) resolves both references, projects their positions onto
the horizontal plane by zeroing vector lane1, and tests squared separation
against D0 squared at1680488..498. It returns true only when that test passes
and1680680 returns false (1680664..670).

1680680 takes the selected route-point record's second vector (entry+10,
32-byte entries) at1680A30..A60, normalizes its horizontal projection and the
horizontal first-character-minus-second-character displacement, obtains their
angle from the dot product, and compares the resulting angle against A/2 at
1680C88..CA0. It is an angular predicate, not a timer. Exact human-facing
direction labels such as behind/in-front are left open.

In167F988 the old +190 is compared against T at167FA08. W receives four booleans
at167FC6C..FC80 through168790C:
  W1 = IsWaitCatchUp && old(+190)>=T
  W2 = horizontal separation>D2
  W3 = angular predicate1680680
  W4 = horizontal separation>D0
After W's update, IsWaitCatchUp is evaluated again at167FC88. If false, +190
is reset to zero. If true,167FF0C..FF28 adds float bits3D088889 (1/30) and caps
the result to T. The final store is167FC9C. Thus the threshold decision uses
the previous value, and this timer measures consecutive qualifying callbacks.

Both branches also maintain R+1B0: once the second character moves at least
two horizontal units from the cached position (squared threshold4 at167FD0C),
its current position replaces the cache at167FE14. This is a spatial sample
threshold, not another elapsed clock.

RECOVERY STATE AND +198 / +1A0

168790C dispatches W+118. Only state2 calls168300C (at16879BC), so these two
timers do not run in every RealTimeEventManager update. State2 also disables
player control through1682F68->SetCanPlayerControl(false). On exit1682F70 first
requires a nonnull R+80 navigator reference and successful navigator resolution
(1682F88 /1682FA8). Only then it calls SetCanPlayerControl(true), stops
pathfinding, sets preferred move state2, and clears R+194/+198/+19C/+1A0 together
(STP XZR,XZR through alias R+194 at1682FCC/FD0); it also zeros the cached position.
Either missing-navigator case returns before these changes. The outer helper
returns to state1 regardless of this cleanup routine's early return.

168300C requires valid first character, first navigator, second character and
selected record. Its horizontal separation comparison uses D2 at1683088 and
1683158..3160.
  When separation>D2: set preferred move state1 via171D458 at16831F8, then set
  the first navigator destination to R+1B0 via171BB88 at1683204.
  Otherwise: compare old(+1A0) against2 at16832A4..B0; when >=2, call
  StopPathfinding at16832B8; then increment +1A0 by1/30 at16832C0..D0.
The far branch does not reset +1A0. This is cumulative in-range time during
the recovery episode, not necessarily an uninterrupted two-second dwell.

Both paths then test old(+198)>=6 at16832D4..E0. Before expiry, +198 advances
by1/30 at16832E4..F8 and the function returns IsPathfinding (16832FC). At expiry,
it calls the fallback1683528 at1683424. During fallback it returns true while
R+194!=4; when substate4 is reached it clears +198 and returns false.
Outer state2 ends only when that return is false AND W2 is false (1687A04..08).
Thus six seconds is a navigation-recovery deadline, not an unconditional wait
before an ordinary NPC conversation.

ORIGINAL CPU CHECKS AND NEXT EVIDENCE

All four increments load float bits3D088889. They do not consume incoming
elapsed time. The private float-cadence-model.json is a binary32 arithmetic
model; a subsequent isolated guest-code harness confirmed its boundary results.
Final event-checks.txt: 750 checks, zero failures, 10 compiled functions.

The test runs original instructions from the capped +190 block, the combined
+1A0/+198 branch region, complete fallback1683528, and complete cleanup1682F70.
Only unrelated extraction continuations were replaced with return markers.
Original arithmetic, comparisons, branches and the fallback jump table are
retained. The exact extraction/return-marker provenance is event-fixtures.json.
External fade/navigation/reference/placement helpers are deterministic stubs;
this test does not exercise their implementation or a game/rendering process.

Confirmed cases include capped +190 values below/at/above configured limits,
its false-predicate continuation resetting it, the far-path timer continuation
preserving +1A0 (entry16832D4, after the actual far-navigation branch),
all fallback entry states0..5 with pending/completed fade status, missing
character references, failed placement still advancing to state2, and cleanup
with a resolved first navigator clearing the three recovery clocks while
preserving the separate +190 clock. Cleanup cases with R+80 null or navigator
resolution returning null preserve those fields and cached position and bypass
navigation/player-control side effects. The far-navigation calls and distance
branch are not executed by the timer continuation fixture.
From zero, the actual old-value checks first act on eligible visits31,62,182
for1,2,6 respectively. Binary32 accumulation reaches2 and6 after61 and181
increments. Preserve comparison order and rounding; these are not bug claims.

The strongest next manual observation is an active scripted walking/catch-up
sequence: identify R, sample W+118/R+194, the four timers and elapsed wall time,
and note control disable/restore and any fade/reposition recovery. This can
establish actual callback frequency at30/60/120. Ordinary dialogue-spam testing
alone may never activate this path. The current static evidence does not prove
