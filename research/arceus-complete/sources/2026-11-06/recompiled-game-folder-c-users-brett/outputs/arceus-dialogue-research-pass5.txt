RESULT
The field-message update path is now traced through the concrete text processor.
It contains a byte-counted reveal delay, an embedded message wait, held-input
acceleration, fresh-press advancement, and an explicit repeat-until-finished
path. They must not all be paced by treating every text-processor call as one
rendered frame. The repeat path intentionally processes many such calls in one
outer update. No timing change or runtime probe was installed in this pass.

These findings strengthen the next diagnostic but do not prove the remaining
reported NPC-dialogue skipping has one of these specific causes. Current live
objects, selected message type, owner flags and observed callback cadence remain
unmeasured. User reports of improved reveal speed are retained as observations;
this pass does not reclassify them as a proven code correction.

per-update progression. Call counts here cannot directly be labeled FPS.
This is a demonstrated control-flow constraint, not a reported live hang.
