3D BLUR: SECOND, SEPARATE CAUSE FOUND

Earlier logging established that the game can use a smaller scene viewport
inside a 2560x1440 image. The existing fixed-resolution candidate suppresses
the automatic resolution governor, while preserving explicit special modes.
That is separate from the shader issue investigated here.

The Vulkan translator exposes guest screen coordinates as physical FragCoord
divided by render scale. Several lighting shaders then convert those coordinates
to integers and fetch G-buffer texels. The old translation rescales the integer
coordinate. The first rounding has already discarded the extra pixel detail.

At scale 4/3, output pixels 0..7 can therefore fetch columns:
  old:       0, 2, 2, 3, 4, 6, 6, 7
  candidate: 0, 1, 2, 3, 4, 5, 6, 7

This pattern was reproduced from the emitted SPIR-V, not just from a separate
formula. It is a confirmed coordinate defect; it is not yet proof that every
part of the visible blur has been fixed.

The candidate recognizes only a conservative instruction chain:
  unmodified screen-position IPA -> 32-bit floor/truncate F2I -> integer fetch
  with optional MOV instructions and verified reaching definitions.

For a texture marked as scaled, the fetch uses the actual physical framebuffer
pixel. Unscaled textures retain the original coordinate. Arbitrary coordinates,
swapped axes, modified values, other rounding modes, packed offsets, and
ambiguous definitions retain the prior translation. Texture-size queries are
unchanged. The flag is part of the shader cache key, so enabled and disabled
SPIR-V cannot be mistaken for each other.

Flag: SNX_ARCEUS_SCREEN_FETCH=1; disabled by default.

SCRIPT FRAME COUNTER: BROADER AI EFFECTS TO INVESTIGATE

The context updater at main+1050E00 gets elapsed seconds from clock channel 1.
At main+1051860..105187C it accumulates:
  context+84: seconds += elapsed time
  context+88: integer frames += 1

This is NOT simply a global frame number. A round-robin context scheduler resets
both fields when a group was processed; additional flags can reset them too.
Consumers receive the accumulated amount since that context's reset.

Getter main+1059A78 returns +88. Fifteen direct call sites in fourteen functions
were inspected. Nearby vtable methods identify these behaviors/parameters:

  AF22E8: TargetPositionKey, DurationKey, JumpHeight, ChargeTime
  AF5438: look-around degree range and MinSpendFrame/MaxSpendFrame
  B32CD4: TurnFramesKey / TurnAngleKey
  B338DC: TurnFrames / TurnAngle
  B35AE0: WaitFrame
  B39184: AddRestValue
  B39998: AddTirednessValue
  B3A3B0: AddUpVigilance
  B40E48: DecreaseHungryValue
  B416EC: DecreaseSleepValue
  B41F90: an AI value consumer with BlackboardKey / MinValue; exact name unresolved
  B530E0: IncreaseHungryValue
  B55380: IncreaseSleepValue
  B55CB8: IncreaseVigilance, with crouching/grass input keys

These hunger/sleep names describe internal AI values, not a newly inferred
player hunger mechanic. Names are from local strings and their vtable neighbors.

Confirmed operations:
- WaitFrame subtracts the getter's result from its remaining count at +13C.
- AddRestValue passes the count to main+1AA03F4, which multiplies the configured
  float increment by that count, adds it to object+8A4, and clamps the result.

This makes the counter a high-priority timing target. It does not establish
which consumers are active in a particular scene or their actual call cadence.
It also does not prove this is the remaining dialogue-skip delay.

The candidate's observation-only getter probe records the paired frame count,
elapsed seconds, flags, object, and caller. The log summarizer reports the ratio
without summing repeated reads of the same accumulated interval. A 30/120 FPS
comparison should establish whether the frame count runs ahead of elapsed time.

Do not replace +88 with floor(+84 * 30): a context reset every fast frame would
discard its fraction repeatedly and could stall WaitFrame. Any later correction
must preserve fractional progress and the scheduler's reset/pause semantics.
No script counter correction has been enabled in this candidate.

NAVIGATION AND RIGID-BODY PHYSICS ARE DIFFERENT CASES

Navigation wrapper main+2795204 selects either incoming dt or 1/30 and passes it
to main+3119908 (local name hkaiWorld::stepWorld). In the inspected callee, the
incoming float is added to asynchronous latency accumulators +4C0 and +4C4.
The profiling label is "Async latency". The asynchronous processing launch is
main+3117A54. This finding weakens the earlier suspicion that this particular
1/30 constant directly makes characters move four times faster. Navigation was
left unchanged; downstream scheduling effects remain a separate question.

Rigid-body wrapper main+2AF25B4 is a stronger candidate:
- +121 chooses incoming dt or fixed 1/30.
- +124 multiplies that chosen duration.
- The result is written into a StepInfo structure and passed at main+2AF2AB4
  to main+2F39630, Havok collision task setup.
- main+2F3B120 then prepares solving; its local strings include Physics, Solve,
  Timestep, Tau, Damping, and Num substeps.

The previous entry probe measured incoming dt and mode, not StepInfo. The new
probe at main+2F39630 logs the actual downstream step_seconds, world object,
caller, and two raw structure words. A future 30/120 comparison can measure
whether fixed steps reach this boundary at render cadence. This still does not
alone prove how every body integrates, and no physics-step change is enabled.

RIDE BLINKING

main+2518BA8 is byte-identical to the already-corrected base blink function.
main+2518CA4 implements the corresponding subobject countdown. These functions
were outside the three confirmed blink hooks. Their cadence and live use remain
unmeasured. Optional probes now record calls and countdown changes without
pacing these additional routines.

All four new observation probes are gated by SNX_ARCEUS_TIMING_RESEARCH=1 and
the exact Arceus 1.1.1 build. Function lengths and instruction guards are checked.
Equivalent LDR/LDUR or B/CBZ-XZR encodings force the existing JIT dispatch path;
they do not change the counter or timestep semantics. Static guard and branch
equivalence checks passed. Live installation and callback coverage remain pending.
